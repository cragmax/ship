# Ship ADR-0001: Unattended runs — a rendered scheduler, a reviewed slice chain, the PR as the sole human gate

Ship performs unattended runs: workflow sources rendered into saved workflows drive a deterministic scheduler over an epic's issues, each built from its triage brief in a slice worktree, reviewed by stage agents that amend its one commit, and landed on the epic's branch, with one pull request per epic as the only human gate. The long-lived orchestrator session it replaces spent half its flow keeping its own context alive, hardcoded repo internals no gate checked, planned in bulk so plans went stale, and idled finished slices behind rung barriers. Restates the retired root unattended-runs record (Framework ADR-0045).

## Decision

### The machine

1. **Orchestration lives in the repo, rendered.** The **Workflow sources** render (`npm run codegen`) into the **Saved workflows** `ship.js` and `resync.js` in `.claude/workflows/`. A Saved workflow loads no code by any route ([Ship PF-4](../platform-facts/workflow-runtime.md)), so the render inlines the entry and the transitive closure of its relative value imports, and `gate:codegen` compares the committed file with a fresh render. Rendered code uses ECMAScript built-ins only: no imports, no `eval` or `new Function`, and (per the workflow-authoring reference, not probed) no `Date.now()`, `Math.random()` or argless `new Date()`. Mechanical steps are commands of the worktree CLI and the run gate, each invoked from the main checkout by a **runner** agent with `node --import tsx` (an `npx tsx` tool is orphaned from the session's process tree, [Ship PF-16](../../../docs/platform-facts/node-runtime.md)) and returning a schema-validated JSON envelope. Judgment steps are **Stage agents**, one skill each, resolved by `agentType` with an output schema ([Ship PF-5](../platform-facts/workflow-runtime.md)), the skill preloaded ([Ship PF-15](../../../docs/platform-facts/claude-code.md)). Rules and live docs state neutral invariants and never name a maintainer-personal skill.
2. **Ship's layout follows where its code runs.** `ship/src/workflow/` runs inside the Workflow runtime, rendered; `core/` holds pure, render-safe decisions used on both sides; `cli/` is runner or session I/O; `schemas/` holds the zod sources for codegen; `build/` renders, emits and checks. A depcruise rule lets `workflow/` and `core/` value-import only each other, plus two carve-outs the render inlines, neither importing anything: `server-pool/src/lease-timings.ts` for `workflow/` only, in place of the pool barrel ([Pool ADR-0001](../../../server-pool/docs/adr/0001-warm-pool-and-lock-file-leasing.md) decision 5), and `tooling/hooks/lib/platform-wide.ts` for the PR body's full-tiers line. Type-only imports are free, since the render erases them. So render-safety is held by folder, not by review. The whole worktree CLI is Ship's, the interactive `commit` command included, since running a CLI is no import edge (Framework ADR-0045 decision 3); Ship's part of `.claude/` stays where Claude Code reads it, listed in [Ship's README](../../README.md) (Framework ADR-0045 decision 5).
3. **Instructions come from the main checkout.** Every agent instruction (`CLAUDE.md`, `.claude/rules/`, skills, agent files, the Saved workflow) comes from the main checkout's working tree when each agent starts; a slice's copies are its diff, never followed, so a run cannot change the rules its later agents obey before the PR is reviewed. Project docs (GLOSSARY, ADRs, platform facts) are read from the tree under review. The run layout makes it so: every run worktree is a direct child of `<main>/.claude/worktrees/`, which gets the main checkout's path-scoped rules and never its own `CLAUDE.md` or rules ([Ship PF-14](../../../docs/platform-facts/claude-code.md)): the **Batch worktree** `ship-<head>`, **Slice worktrees** `ship-<head>-<N>-<K>` (`ship-<head>-a<R>-<N>-<K>` for an **Attached run**). The run root, its report dir, is `<main>/reports/ship-<head>/`; an unlanded slice's work is kept under `<main>/reports/kept/`. All are gitignored, and Windows' 260-character path limit sizes the names. Guards: `provision-batch` refuses a report dir inside the batch or a slice; `retire-run` removes only a real `ship-*` directory directly under `<main>/reports/`; `teardown` and git refuse the main checkout, and teardown restarts the session's tsserver after removing a worktree ([Ship PF-17](../../../docs/platform-facts/claude-code.md)). A dirty main checkout is recorded, never refused. Accepted residuals: a slice missing its `node_modules` junction resolves modules from the main checkout's, silently, and a manual recursive clean in the main checkout reaches live runs.

### Launch

4. **Pre-flight runs while the maintainer is present, collects every refusal and never pauses.** In order: the checks (master level, `gh` logged in, the **Warm set** warm), the **Run gate**, `live-runs`, the `issue-readiness` agent once over the run set, then the `issue-overlap` agent once over what is left and the unspent live runs' changed files. No check stops the phase early; a missing or partial verdict is a refusal, never a pass. A leftover slice branch refuses unless its run is spent. Once pre-flight passes, the spent runs' batches are torn down and their runs retired (`--preflight-only` stops before).
5. **The run gate is rubric point 2 inside a run.** The run set is an epic's open children (the container is never gated) or an explicit list, several epics allowed. Each issue must be open and `ready-for-agent`, every `blocked_by` closed or inside the run set; in-set edges become scheduler edges and a cycle refuses. A failure refuses the launch, listing every failing issue; exclude mode drops the failures, a stale or not-ready verdict among them, with their transitive dependents. Each issue's label is re-checked when it becomes ready; a removed label skips it and its dependents.
6. **Overlap edges, estimated before anything is built.** The `issue-overlap` agent estimates which issues will touch the same files, from the issue text and the tree, adding the edge when unsure. A pair is directed along a topological order of the declared edges (ties by run-set order), so the union stays acyclic; a pair whose every shared path is a generated file adds none. An overlap between two epics, `unsure` included, or with a live run, refuses the launch: the epics of a run, and concurrent runs, are code-disjoint.

### The issues

7. **A deterministic scheduler with optimistic requeue.** Rendered JS, no LLM, no context budget: each issue starts as soon as its dependencies have landed, under one `MAX_SLICES` cap (4) across all the run's epics, with no rung barriers. The drive loop races un-awaited flights with `Promise.race` in completion order ([Ship PF-7](../platform-facts/workflow-runtime.md)). A slice holds its slot until it settles, the commit-queue wait included; epic ends run outside the cap. On a harvest conflict the slice is discarded and re-cut from the current epic head (the requeue); one confined to `eslint-suppressions.json` is regenerated instead. A dead agent is retried once from a fresh worktree, then its issue is blocked; a blocked issue skips only its transitive dependents. A landing that leaves the batch unverified halts that epic: no further starts or landings, no epic end, no PR; its in-flight slices are torn down, its unlanded issues cited `see #N`, and the run's other epics carry on.
8. **The slice chain.** Each attempt runs in its own Slice worktree cut from its epic's head: label re-check → cut → provision → tdd → **Spec review** → **Test review** → **Standards review** → Script API TSDoc → land. Planning happened at triage: the tdd builds from the issue, its brief the plan, sized by the ticket-time **Slice budget**; an issue the tree has overtaken, or whose named mechanism a probe falsifies, is blocked before any commit. The tdd makes the slice's one commit and chooses `fixes` or `see` (`see` for an acceptance line that needs a human). Each review verifies its findings against the code, applies them once and amends that commit: no re-review loop, so a review has a fixed cost; after an amend the slice's changed files are re-read from git. A blocked review stops the slice. Test review is skipped on a trivial surface (no path under the code prefixes) or when `comment-only` proves the commit comment-only; Script API TSDoc runs only when the slice changes `src/`. Each stage runs only the tests its change makes relevant (`write-testing.md` § Which tests a change runs); server-tier runs take **per-invocation leases** on the Warm set through `with-lease`, 600 s each.
9. **Probes inside a run** are pre-approved and lease-bound, capped at 15 min per probe and 3 per stage, each record carrying its measured `seconds`; enforcement is the agent's. A command that can outlast a call's 10-minute cap goes to the background, polled by chained foreground `timeout 570 … until` calls, the turn never ended while it runs ([Ship PF-6](../platform-facts/workflow-runtime.md)). A cap hit or inconclusive probe records nothing and adds a PR follow-up. Rig-reconfiguring probes (a plugin jar swap, a compose or `server.properties` change, a Docker restart) block the issue.
10. **One branch and one commit queue per epic.** All of a run's work lands on the epic's `ship/<slug>` branch in its Batch worktree without per-commit consent: issue commits, the `origin/master` merge and the bump. Per-slice branches are scratch, never pushed or merged. The **Commit queue** lands one commit per issue, `fixes #N` or `see #N`, the staged set guarded equal to the slice's files, under lefthook. A failed pick, build or commit is rolled back with `git reset --hard HEAD` in the batch worktree only, never the main checkout (maintainer-approved 2026-09-28).
11. **The Warm set is 2 Paper + 2 Folia.** A run's slices are Pool ADR-0001's per-invocation consumer on the four registry servers the batch's registry trim keeps; pre-flight requires all four warm. Four servers peaked at about 16.6 GiB together with no OOM and TPS never below 19.6 ([Pool PF-1](../../../server-pool/docs/platform-facts/pool-capacity.md)).

### The epic end

12. **The epic end, in order.** Once an epic's last slice settles: the **epic review** over the batch → the master sync, under the run's repo lock (a merge of `origin/master` if it moved, never a rebase; any conflict but the lockfile's and the version line's stops the epic; amended 2026-10-21: a doc-index conflict no longer goes to a resolver agent, which never ran in a recorded run) → the bump → the **retro** and the `pr` agent, concurrently → the publish task, under the repo lock: a look at the main checkout, a forward-only check of `master` since launch, the push, the PR → a comment on each issue the run blocked, giving the reason and the PR or branch.
    - **The PR is the sole human gate.** The Workflow tool takes no mid-run input. A rejected or empty epic-review verdict opens the PR as a draft.
    - **The push is the server tier.** The epic end runs no server-tier step of its own: its push goes through the pre-push hook, which runs the server tier on both engines when the pushed range touches a Platform-wide path ([Tooling ADR-0002](../../../tooling/docs/adr/0002-change-scoped-pre-push.md); amended by it 2026-10-16: the push ran the full server tier on every range before), so a red tier refuses the push and no PR opens; `npm run test:nightly` is the backstop.
    - **The retro runs for every entry that was cut** (shipped, halted, stopped or with nothing landed), its findings in the PR body. An epic end that stops after the retro re-runs it over the final report and keeps only the re-run's findings.
    - **Resync** shares the master sync: the `resync` Saved workflow brings an open run branch level with `origin/master` and pushes unforced through the pre-push hook after an open-PR check, never GitHub's server-side update.
    - The fetch- and push-bearing steps of every epic end are serialised by the one repo lock. A failed issue comment is recorded, never fails the run; the run changes no label.
13. **The PR body.** Summary and Merge Danger from the `pr` agent over the net diff; Evidence from each landed slice's tdd tracer record; the issue lines (`fixes`, `see`), each with its `Test review:` line; a `## Recorded` section of each issue's recorded values; the lease timings; whether the full tiers ran at push; the run report folded. A `pr` agent that returns nothing still publishes, its sections marked unavailable. A body over GitHub's 65,536-character limit moves the report's Overlap edges, Schedule and Retro findings to PR comments, each leaving a pointer line; `publish` refuses a body still over the limit before the push.
14. **One net version bump per PR.** Issue commits never bump: per-slice bumps on concurrent branches conflict on the version line. The kind is `minor` when any of the branch's own non-merge commits since `origin/master` is a `feat`, else `patch`; the target is `origin/master`'s version bumped by that kind. A branch already at the target gets no commit, otherwise one bump commit sets it. A resync merge sets the version to `master`'s bumped by the branch's own bump, also when both sides bumped to the same number, so the net stays one.
15. **Per-stage tiers are set in one table.** The tier table holds every stage's `agentType`, `model` and `effort`, passed on each `agent()` call ([Ship PF-3](../platform-facts/workflow-runtime.md)). Agent files carry no model pin: a frontmatter pin is honoured when no per-call `model` is passed ([Ship PF-5](../platform-facts/workflow-runtime.md)), so it could silently override the table.

### Attached runs and recovery

16. **Attached runs.** `/ship issues N… --attach ship/<slug>` lands issues on an open PR's existing branch and pushes onto that PR; `epics` with `--attach` is refused, and the run has one entry. Pre-flight refuses the target on `no-open-pr`, `slices-live` or `unpublished-commits` (first-parent non-merge commits `origin` lacks); `issue-readiness` and `issue-overlap` judge the PR head, the overlap check skipping the target only. Setup reuses the branch's Batch worktree or checks it out anew; the entry's base is the attached tip, and the run takes the lowest number R no earlier `attach-<R>/` report folder or `a<R>-` slice branch holds. The epic end is epic review over this run's slices, master sync, bump and retro (no `pr` agent), then a push onto the open PR; a PR closed meanwhile stops the epic. After a successful push the run's report is posted folded as one PR comment and one `## Attached run <R>` section (Evidence, Issues, Recorded, a link to the comment) is appended to the PR's body, everything already there kept byte for byte, the closing-keyword neutraliser run over the new text. A body or comment over the limit is refused before `gh`; a refused or failed push posts and edits nothing; a failed post or edit never fails the run.
17. **Resume only a one-flight run; recover every other by hand.** The Workflow runtime's resume replays cached results for the longest unchanged prefix of `agent()` calls, keyed by position; with more than one flight the call order follows real settle timing, so a replay breaks the prefix at the first overlap and re-runs landed issues. Resume is supported only for a one-entry run launched with `--max-slices 1` whose script is unchanged, or changed only in code after the last finished call. Manual recovery: stop the run, then write and run a continuation script, the run's script with its entry point replaced by a direct `epicEnd` call whose `EpicEndInput` is copied from the run's journal as literals, since a script reads no files. A stopped attached run leaves its fixes unpublished, and a later attached run's pre-flight and `/resync` refuse (`unpublished-commits`) until a continuation epic end pushes them with `publish --push-only` and appends its section. Stopping a run neither ends its in-flight tool's process tree nor releases that tool's lease.

## Alternatives considered

- **Import the gate and scheduler into the Saved workflow.** Impossible ([Ship PF-4](../platform-facts/workflow-runtime.md)).
- **Rung-barrier scheduling.** Rejected: epic-986 idled four finished slices for 34 min.
- **Bulk planning before the run, or a planner inside each slice.** Bulk plans went stale against later landings; the per-slice planner and plan review were retired for the triage brief.
- **Pessimistic overlap serialisation.** Rejected: the estimate precedes any build, so it would serialise most of an epic, and the requeue makes a miss self-heal.
- **Mid-run gates or per-commit consent.** Rejected: the Workflow tool takes no mid-run input, and either defeats AFK.
- **Model pins in agent files.** Rejected: 46 runs once ran a judgment agent on a different model than the session, and a pin can override the table.
- **An epic-end-only `/ship` mode fed from run state under `reports/`.** Deferred until parallel or multi-epic runs are routine; manual recovery covers them. **Deterministic replay for parallel runs.** Rejected: lockstep rounds would undo completion-order scheduling.
- **A run root outside the project, or under `tmp/` or an untracked dot-directory.** Rejected: outside the project no path-scoped rule loads ([Framework PF-90](../../../docs/platform-facts/claude-code.md)); inside but not under `.claude/worktrees/`, a worktree loads its own `CLAUDE.md` and rules (Ship PF-14). **Full-slug worktree names.** Rejected: the longest list slug puts a slice's deepest path near 300 of Windows' 260 characters.

## Consequences

- The scheduler exists twice, source and render, held together only by `gate:codegen`.
- A missed overlap estimate wastes one slice's build (the requeue); mid-run steering is limited to removing a label; a rejected PR rejects a whole epic's work at once.
- `MAX_SLICES` and the probe caps were confirmed on real runs, not tuned by a controlled measurement; long commands need the background-and-poll idiom.
- A run of more than one flight cannot be resumed once cut, only recovered by hand.
